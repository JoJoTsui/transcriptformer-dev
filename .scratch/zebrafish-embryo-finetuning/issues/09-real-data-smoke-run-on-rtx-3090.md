## Comments

Smoke run (2026-08-26, RTX 3090, WSL2): `transcriptformer finetune --manifest smoke_run/manifest.json --max-steps 2 --batch-size 8 --device auto --precision 16-mixed` completed in 2m50s wall (~2 min of it model/vocab loading from the slow drvfs mount), peak RSS 15.6 GB, training loss 15.72 -> 14.09 over 2 steps, 4.3 GB checkpoint written. Artifacts in `.scratch/zebrafish-embryo-finetuning/smoke_run/run/`. Data: contract-complete embryo H5ADs on the real zebrafish vocabulary (30,312 ENSDARG genes from the Metazoa checkpoint; synthetic NB counts), generated by `smoke_run/make_data.py`.

Findings during the run:
1. The venv held a **stale non-editable install** of transcriptformer 0.6.1, so the `transcriptformer` CLI entry point ran old code regardless of repo edits. Fixed with `uv pip install -e . --no-deps`. Tests were unaffected (pytest uses `pythonpath=["src"]`).
2. `derive_batch_plan` reduced the requested `--batch-size 8` to per-GPU batch 1 (gpu_plan recorded in the manifest) — conservative but surprising; worth revisiting when tuning production runs.
3. The multi-GPU item stays open: this machine has a single RTX 3090, so DDP has still never launched.
4. A first attempt with `--validation-interval 2` ran >55 min without completing (mid-run validation over 2000 validation cells at batch 1 dominated); rerun with interval 100 completed. Validation cadence matters at real scale.
