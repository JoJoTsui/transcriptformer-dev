# Non-zebrafish online gate follow-up — 2026-09-29

This note supplements the [gate inventory](non-zebrafish-gates-2026-09-29.md). It uses first-party documentation to identify obtainable inputs and leaves project-specific scientific choices open. No Census slice, benchmark table, or model result was downloaded or frozen here.

## Adult forgetting reference

The [CELLxGENE Census release page](https://chanzuckerberg.github.io/cellxgene-census/cellxgene_census_docsite_data_release_info.html) lists `2025-11-08` as a dated long-term-support release; `stable` is an alias and weekly `latest` releases are short-lived. This makes `census_version="2025-11-08"` a concrete **candidate** for the human/mouse reference, not a project-approved freeze. Its schema has `dataset_id`, `donor_id`, `is_primary_data`, `development_stage`, `disease`, `tissue_type`, `tissue_general`, and assay fields in cell metadata, and unique `feature_id` in gene metadata ([schema](https://chanzuckerberg.github.io/cellxgene-census/cellxgene_census_schema.html), [query guide](https://chanzuckerberg.github.io/cellxgene-census/notebooks/api_demo/census_query_extract.html)). In this release, some `disease` values contain multiple labels separated by ` || `, so a bare equality filter for `normal` can miss eligible or conflicting cells ([release notes](https://chanzuckerberg.github.io/cellxgene-census/cellxgene_census_docsite_data_release_info.html)). Census includes organoids as well as tissue observations, and marks duplicate representations through `is_primary_data` ([schema](https://chanzuckerberg.github.io/cellxgene-census/cellxgene_census_schema.html)).

**Executable intake contract after approval:** query metadata first; restrict to primary, adult, normal, tissue observations using explicit ontology/label rules and an explicit policy for multi-valued disease; exclude any `dataset_id` or donor overlapping training/holdout sources; stratify the planned 2,000 cells per species across at least five tissues; record the dated release, exact filter, selected observation IDs, dataset/donor IDs, feature IDs, source hashes, and sampling seed. Fetch counts only for selected IDs after estimating size. The 2,000-cell and five-tissue targets come from the [local design](../perturbation-and-baseline-design.md#41-reference-set-frozen-never-trained-on), not Census. The project still needs to accept the release, adult/normal ontology rule, assay mix, sampling allocation, and download/compute budget. A public release cannot supply those decisions.

## B3 external benchmark labels

The [MGI report index](https://www.informatics.jax.org/downloads/reports/index.html) describes `MGI_PhenoGenoMP.rpt` as **genotype** phenotype annotations, with allelic composition, background, marker IDs and citations; `MGI_GenePheno.rpt` specifically excludes conditional mutations. The file is an evidence source for positive phenotypes, but absence of a phenotype row is not a tested viable control. A viability comparison therefore needs an explicitly screened denominator and genotype/allele restrictions, for example from a pinned [IMPC release](https://www.mousephenotype.org/data/release) with its viability calls. The gene-level collapse and stage-window labels are project rules, not implied by the MGI file.

The [FlyBase download specification](https://wiki.flybase.org/wiki/FlyBase%3AFilesOverview) describes `genotype_phenotype_data_*.tsv.gz` rows as genotype, phenotype, qualifier and publication records; its [bulk-download page](https://flybase.org/downloads/bulkdata) exposes release-labeled files. Those rows likewise cannot be treated as one tested gene each or as a complete set of negatives. Before an embryonic-lethality AUROC, choose allele/genotype filters, how to handle multi-gene genotypes, the tested negative universe, and a pinned release; preserve original row and publication identifiers. This is the actionable non-zebrafish FlyBase set. The [local B3 design](../perturbation-and-baseline-design.md#2-external-falsification-sets-s1) also proposes WormBase and other sets, but no source download can replace real model scores or sign off the verdict.

## Ticket 05 paired comparison

The [ticket](../../.scratch/multispecies-readiness-remediation/issues/05-statistic-specific-ortholog-eligibility.md) already produces eligible one-to-one gene pairs and a hash-bound paired-score handoff. It still lacks observed B3 null-corrected scores and a frozen comparison question. A workable **method proposal for review** is to use the full eligible ortholog universe, report paired score scatter and Spearman rank concordance per species pair and phase, and summarize paired score differences descriptively. Keep independently selected top-200 overlaps as a separate, selection-conditioned statistic. This follows the [SciPy definition of Spearman correlation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.spearmanr.html); SciPy warns that its asymptotic p-value needs very large samples and suggests permutation for small samples. A Wilcoxon signed-rank test would answer a different question, assumes symmetric paired differences, and requires a declared zero/tie policy ([SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.wilcoxon.html)). These method facts do **not** authorize a cross-species inference: gene pairs share pathways and embryo-level score uncertainty, and top-selected genes are a biased universe for a genome-wide distribution claim.

Before analysis, freeze the intended universe, score definition and comparability check, phase and species pairing, effect size, uncertainty/null procedure, multiple-comparison family, minimum denominator, and how missing/ambiguous pairs are reported. Then obtain actual B3 score tables and ranking provenance, run the existing handoff, and publish the paired denominator and exclusions. No online document can determine these project-specific rules or create the missing model outputs; ticket 05's last acceptance item remains open.
