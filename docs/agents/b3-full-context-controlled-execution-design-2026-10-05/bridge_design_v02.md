## Registration is a separate software and data gate

The native catalog checks the original producer's plan/config/checkpoint,
deterministic declarations, software and original common-file bytes
(`b3_native_catalog_pages.py:273–365`). That contract does not itself prove
prospective family/source-key registration, every old execution-context field,
or biological embryo independence. New rows supply none of those missing facts.

The bridge needs a genuine immutable prospective registration, derived from
original approved preparation/cohort/producer evidence. Its intended new type
is `b3_full_context_family_registration_v2`. It binds:

- The exact existing `b3_measured_zero_bootstrap_family_v1` byte reference,
  canonical family SHA, model arm, comparison order, and each original absolute
  `bundle_a`/`bundle_b` source key. Receipt/cache/output paths cannot replace keys.
- Each source's original config and native plan references, species, phase,
  split, arm, cohort identity, complete configured gene axis and physical embryo
  identities, original prepared/source bindings and selection/split decisions.
- Manifest/preparation report, full preflight, paired preflight/table for every
  registered member, checkpoint weights/config and complete gene/aux vocabulary
  references, metric normalization and original producer/scoring code identity.
- The actual prospective decision/freeze record. A timestamp or freshly written
  JSON assertion alone does not establish that the family preceded outcomes.

The registration software validates metadata without tensors/forwards. A
completed metadata receipt attests no chronology. The new actual controlled
issuer/producer must enforce durable registration/start before computation and
retain a typed witness plus independently captured runtime admission. Section7
binds their exact sources/run/permit/output and external authority pin. The
bridge never executes the issuer or invents that capture; code listings and
consistent JSON are insufficient. Until this prior dependency is independently
accepted and the actual run externally admitted, positive compare refuses.

Genuine imported-pilot evidence can carry actual original provenance:
`import_b3_measured_zero_pilot_shard.py:156–171` binds `pilot_bundle_path`, all
six original files and the canonical original producer digest. Authenticate
those originals and their original registered paired/family fields; do not
promote an import declaration into effect recomputation. No imported receipt
may be created merely to satisfy the new bridge.

The existing six-source real corpus has useful preparation inputs at
`runs/b3_pilot/full_organogenesis_v3/manifest.json`, `prepared_run/`, and
`prospective_split_plan.json`. The recommendation record reports preserved
human decisions and prospective physical mouse splits. The full preflight
already emits exact source/prepared paths/SHAs, survivor digests, split, selected
membership digest and cohort identity (`preflight_b3_measured_zero_full.py:437–460`).
Those are reusable facts; prepared observations are not scored native shards.
The full preflight JSON does not contain the complete embryo ID list: a
registration must bind genuine identity/split evidence and later match the
actual native proofs and metric axis, not invent IDs from `n_embryos`.
